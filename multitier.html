What is Multi-tier Architecture?

Multi-tier architecture (often called n-tier architecture) is a client-server design pattern that separates an application into logical layers (tiers). Each tier has a specific responsibility, making the system more organized, scalable, and secure.

Key Fact: Most modern web applications use a 3-tier architecture: Presentation, Application/Logic, and Data.

The 3-tier model separates user interface, business logic, and data storage.

The Three Main Tiers

  • Presentation Tier (User Interface): The web browser, mobile app, or desktop UI that users interact with. It sends requests and displays results.
  • Application Tier (Business Logic): The middle layer that processes requests, applies rules, and coordinates data. Often runs on a web server or application server (e.g., Java, Node.js, Python).
  • Data Tier (Database): Where information is stored and retrieved. Examples: MySQL, PostgreSQL, MongoDB.

Benefits of Multi-tier Architecture

  • Scalability: You can scale each tier independently (e.g., add more application servers without touching the database).
  • Security: The data tier can be hidden from direct user access.
  • Maintainability: Changes to one tier don't break the others.
  • Reusability: The same business logic can serve different clients (web, mobile, API).

Real-World Example

When you log into Amazon:

  • Presentation: Your browser shows the login form.
  • Application: Amazon's servers check your password and create a session.
  • Data: The database stores your encrypted password and user profile.
